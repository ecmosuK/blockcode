# BlockCode ESP32-S3 ELF app template

This is the compiler template used by `tools/build-service.py`. The service
replaces `main/blockcode-app.cpp` with the C++ generated by the web app, runs
`idf.py build`, then wraps `build/blockcode_app.app.elf` in Quantum OS's `.app`
header and 48x48 icon slot.

From PowerShell, start the local service with:

```powershell
& "C:\Users\kaede\Documents\nasa watch\tools\start-build-service.ps1"
```

Leave that PowerShell window open while using the page, then open
`http://127.0.0.1:8765/` in the browser. The service serves the web UI as well as
the build API so it can rasterize and embed the selected/built-in/custom sprites.
**Build watch .app** downloads the built package. **Upload to Watch** builds it and sends it over the watch's USB-Serial-JTAG
connection into `/sdcard/apps`; connect and power on the watch first. The local
service uses `tools/push-app.py` from the Quantum OS project, which it expects at
`~/Downloads/quantum-os/quantum-os` by default. Set `QUANTUM_OS_DIR` before
starting the service if the project is elsewhere. The service is bound only to
`127.0.0.1:8765`; it accepts requests from local files, localhost pages, and the
configured hosted website origin. When using the hosted site, keep this service
running and allow the browser to access local network devices if prompted. If a
browser blocks that connection, open the local URL above instead. Uploads use
the local Python uploader rather than the browser's Web Serial API, so they do
not depend on a browser-specific COM-port picker. The first build may download
the Espressif ELF loader component and take several minutes; later builds reuse
a local build cache.

When using the Render-hosted site, the browser sends the finished package to
the watch directly using Web Serial; this requires Chrome or Edge over HTTPS
and the watch connected to the computer running the browser. The Render server
builds the app but never accesses the computer's USB port.

For a different ESP-IDF installation, start the service from an ESP-IDF-exported
shell so `IDF_PATH`, `IDF_TOOLS_PATH`, and `IDF_PYTHON_ENV_PATH` point at it.

The package format is declared in Quantum OS `main/os/app_format.h`. Its code
payload is the ESP-IDF ELF app image; `code_off` and `code_size` point to it.
`entry_off` is reserved because the ELF loader takes the ELF entry point from
the ELF image itself.

Generated app actions call the `qos_app_*` display ABI provided by Quantum OS.
The app linker intentionally leaves those firmware API references unresolved;
the ESP32-S3 ELF loader resolves them when the app is tapped. Newly generated
apps show a movable sprite and speech bubbles on the watch, and can be dismissed
with a downward swipe. Each build embeds the current sprite and every sprite
referenced by a `switch sprite` block as RGB565-alpha image data, so uploads do
not depend on web assets being present on the watch. Say/Speak blocks are also
synthesized into offline English PCM clips by Windows Speech at build time and
played through the board's ES8311 codec and speaker amplifier; tone blocks use
the same speaker output.
